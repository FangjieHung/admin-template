# ADR 0007：質地與配色改為白名單相容，質地為主軸

- 狀態：已決策、機制已實作（2026-09-26）；相容清單已定案（2026-09-27）
- 日期：2026-09-26

## 背景

ADR 0002 的前提是「自由組合」：組合矩陣每一格都必須可讀、可操作。擴充到 7 種質地 × 8 種配色（56 格）後，部分組合（例如 Soft UI × Sandstone、Soft UI × Verdant）對比過弱或不協調。逐格修到全部可用的成本高，而且會讓每個質地的造型被迫遷就最難搭的配色。

## 決策

1. 每個質地宣告自己的**相容配色**（白名單）與一個**預設配色**。新增配色時預設不相容，必須逐一加入。
2. **質地是主軸**：質地選項永遠全部顯示；配色選項只顯示目前質地的相容配色，不相容的直接隱藏。
3. 切換質地時，若目前配色不相容，改用該質地的預設配色；載入時若 localStorage 存的組合不相容，同樣自動校正。
4. 白名單的初版由對比掃描腳本（WCAG 4.5:1）先篩，再由設計者依美感刪減。

## 考慮過的替代方案

- **黑名單**（預設全開、只擋壞組合）：新增配色會自動出現在所有質地，難看或不可讀的組合要等人發現才擋，與「可讀性不可妥協」衝突。
- **只推薦、不擋**：使用者仍能選到不可讀的組合。
- **兩軸互相過濾**：會出現某個質地永遠選不到的死路，所以固定由質地當主軸。

## 後果

- 取代 ADR 0002 第 5 條「所有組合均須可讀」，改成「所有**相容**組合均須可讀」。
- 相容清單只存在 TS registry 一處；質地準則文件只引用它，不重抄。

## 定案清單（2026-09-27）

由設計者依美感挑選；定案前 56 格對比已全數合格（ticket 15），所以排除的理由都是美感，不是可讀性。實際清單以 `theme.token.ts` 的 `TEXTURE_COMPATIBILITY` 為準，下表只是當天的快照。

| 質地 | 排除 | 預設配色 |
| --- | --- | --- |
| Material | Candy | Verdant |
| Linen | Candy | Sandstone |
| Grid | （無） | Verdant |
| Soft UI | Sandstone、Verdant | Cool Grey |
| Clay | 只保留 Midnight、Cool Grey | Cool Grey |
| Editorial | Cool Grey | Mist Ink |
| Frosted | Sandstone、Cool Grey | Candy |
